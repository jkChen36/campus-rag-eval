# 校园教务 RAG 问答系统 · 效果评测

一个从零实现的 RAG 系统，以及一套用来测量它的评测体系。

> 搭一个 RAG 现在半小时就能跑通，难点从来不是"搭起来"，而是**回答"它到底好不好、好在哪、差在哪"**。
> 这个项目把重心放在后半句：100 条分层评测集、9 组对照实验、双指标归因、10 条 badcase 分析。

---

| 指标 | 基线（语义切分 + Top-5） | 最优配置（Top-10 + 重排 + Prompt v2） |

| 答案准确率 | 74.0% | **90.0%** |
| 召回命中率 | 78.8% | **92.5%** |

## 二、项目做了什么

### 1. 数据采集与清洗

- 面向学校官网、教务处及二级学院站点实现栏目翻页解析与附件批量下载，采集 **46 份教务制度文件（约 8.7 万字）**，覆盖学籍管理、奖励与处分、学位授予、宿舍管理等核心制度；
- 部分历史文件是 OLE2 二进制 `.doc`，本机无 Word / WPS / LibreOffice，**设计 UTF-16LE 整文件解码 + 中文片段正则提取方案还原正文**，成功转换 4 份（单份最多还原 3,294 字）；
- 关键词黑白名单降噪，剔除通知、新闻类非制度文件，最终切分为 **260 个可检索片段**。

### 2. RAG 问答系统

- 检索链路全部手写实现（解析 → 切分 → 向量化 → 召回 → 重排 → 生成），**不依赖 LangChain 等框架封装**，检索部分基于 numpy 手写余弦相似度，全项目仅 4 个依赖；
- 向量模型 `BAAI/bge-m3`（1024 维），生成模型 `deepseek-chat`，重排采用 LLM 打分；
- 提供三种切分策略：`fixed`（固定长度）/ `section`（按"第 X 条"）/ `semantic`（语义切分）；
- Prompt 分两版，`v2` 增加三条约束：强制依据资料作答、多份文件冲突时以最新年份为准、用户说法与资料冲突时必须指出并纠正。

### 3. 效果评测体系

- **100 条分层评测集**，覆盖直接检索 30 / 多跳推理 20 / 拒答 20 / 时效冲突 15 / 对抗诱导 15；
- 自动判分脚本：LLM-as-Judge 判定答案正确性，同时输出**召回命中率 / 答案准确率 / 幻觉率 / 拒答正确率**四类指标；
- 一键跑 9 组对照实验的脚本，自动判断是否需要重建索引、自动跳过已完成组；
- 自动生成归因报告（含分题型表现、瓶颈判定、badcase 归类）。

## 三、快速开始

```bash
# 1. 装依赖
pip install -r requirements.txt

# 2. 设置 API Key
export EMB_API_KEY="你的硅基流动 Key"    # 用于 embedding
export LLM_API_KEY="你的 DeepSeek Key"   # 用于生成与判分

# 3. 切分语料（fixed / section / semantic 三选一）
python step1_load.py semantic

# 4. 向量化
python step2_embed.py

# 5. 单条问答（可选）
python step3_ask.py "累计补考 7 门次还能拿学位吗？" 10

# 6. 跑评测（单组）
python step4_eval.py E2_semantic_top5 semantic 5 0

# 7. 跑全部 9 组（约 40-70 分钟，自动跳过已完成组）
python step5_run_all.py

# 8. 生成归因报告
python step6_report.py
```

> `chunks.json` 与 `vectors.npy` 未纳入版本库（体积较大），clone 后按第 3、4 步重建即可。
> 全程 API 开销约 3-8 元。

## 四、评测集是怎么设计的

题型分层的目的，是让评测集**能区分出系统的真实短板**——如果五类题型都拿到 90%，这份评测集就没有价值。

| 题型 | 条数 | 考察点 | 例子 |
|---|---|---|---|
| 直接检索 | 30 | 基础召回能力 | "休学一般以多长时间为期限？" |
| 多跳推理 | 20 | 跨文件综合 | "挂科了还能评奖学金吗"（需同时用学籍与奖励两份文件） |
| 拒答 | 20 | 会不会编造 | "学校一年的学费是多少钱"（资料中无） |
| 时效冲突 | 15 | 新旧政策以哪个为准 | "累计补考 7 门次还能拿学位吗"（2012 版与 2015 版规定不同） |
| 对抗诱导 | 15 | 会不会跟着用户的错误前提走 | "奖学金名额提高到 20% 了吧，对吧？"（实际为 4%） |

**三层校验**：

1. 每条标准答案的依据原文均从真实语料中逐字提取，写入前做 100% 命中校验 —— 80 条有依据的题目全部命中，0 条未命中；
2. 20 条拒答题做反向校验，确认语料中检索不到相关内容，避免"模型答对了却被判错"；
3. 拒答题不计入召回率统计（它们本就没有依据），单独统计「拒答正确率」，否则会硬拉低召回率约 20 个百分点。

> 第一版评测集是按"通用大学"口径编的，在真实语料里命中 0/11 —— 照它跑召回率会全是 0，所有结论都是假的。
> 旧模板保留在 `eval_set_旧模板备份.csv`，用来对照。

## 五、9 组对照实验

| 实验 | 切分 | Top-K | 重排 | Prompt | 召回 | 准确率 | 幻觉率 | 时延 |
|---|---|---|---|---|---|---|---|---|
| E1 | fixed | 5 | 否 | v1 | 75.0% | 67.0% | 7.0% | 0.86s |
| E2（基线） | semantic | 5 | 否 | v1 | 78.8% | 74.0% | 9.0% | 0.90s |
| E3 | semantic | 3 | 否 | v1 | 68.8% | 66.0% | 6.0% | 0.86s |
| E4 | semantic | 10 | 否 | v1 | 92.5% | 73.0% | 8.0% | 0.91s |
| E5 | semantic | 5 | 是 | v1 | 86.2% | 78.0% | 6.0% | 1.53s |
| E6 | section | 5 | 否 | v1 | 72.5% | **63.0%** | 5.0% | 0.85s |
| E7 | semantic | 10 | 是 | v1 | 92.5% | 70.0% | 10.0% | 1.65s |
| E8 | semantic | 5 | 否 | v2 | 80.0% | 84.0% | 6.0% | 1.10s |
| **E9（最优）** | semantic | 10 | 是 | v2 | **92.5%** | **90.0%** | **4.0%** | 1.89s |

## 六、四个关键发现

**1. 准确率上不去，不一定怪检索 —— 用双指标定位瓶颈**

E4（Top-10）召回冲到 92.5%，准确率却停在 73%，差 19.5 个百分点。检索明明能找到，准确率就是上不去，说明瓶颈在生成环节。于是在**完全相同的检索配置下只改 Prompt**，准确率直接到 90%。

判据：召回高、准确率低 → 问题在 Prompt / 上下文组织；召回低 → 问题在切分 / 检索。

**2. 重排（Rerank）单独加是负收益**

E7（K10 + 重排）70.0%，反而低于 E4（K10 无重排）73.0%。重排把更多片段排到了前面，模型不会筛选反而更糟。但配上 Prompt v2 后，E9 才冲到 90%。结论：重排的价值取决于下游 Prompt 能否消化更多信息。

**3. 按"第 X 条"切分是最差的（63%）**

比固定长度切分（67%）还低。原因是学校公文是"长表格 + 条款叙述"混排，按条款切会把表格结构切碎。语义切分（74%）才是对的。

**4. Prompt 变强是有代价的**

v2 让模型更愿意回答，代价是 20 条拒答题里误答了 1 条，拒答正确率从 100% 掉到 95%。这是真实的权衡，不是掩饰缺陷。

## 七、典型 badcase

以最优配置 E9 为例，10 条失败样本中 4 条集中在「时效冲突」：

> **问**：我累计补考了 7 门次，还能拿到学位吗？
> **答**：根据资料[8]第七条（五），全学程考试课程普通本科累计补考 6 门次（含 6 门）以上者不授予学士学位……（错误：引用了 2012 版旧文件）
>
> **问**："不授予学位"的情形，现在看哪一份文件？
> **答**：资料中涉及多份文件，且未明确标注各文件的年份，无法判断哪一份最新。

模型自己说出了根因：**检索到的片段里没有带来源文件名**，两版学位细则摆在面前却分不清哪个是 2015 版。

已针对此完成修复：在 `step3_ask.py` 中加入 `INCLUDE_SOURCE` 开关，为每个片段附加带年份的来源文件名（对应实验 E10，尚未完整复跑）。

## 八、已知局限

- **时效冲突仍是最弱项**（73.3%），模型对多版本文件的年份判断不稳定；
- **拒答正确率 95%**，存在 1 条本应拒答却作答的情况；
- **评测集本身有瑕疵**：其中"学校一年的学费是多少钱"被标为拒答题，但语料中确实存在"工商管理学院各专业学费 3400 元/年（2013 年文件）"，属标注错误。发现评测集自身的问题，本身就是评测工作的一部分；
- 判分使用 LLM-as-Judge，存在判分模型自身偏差，未做人工复核抽样；
- 语料仅覆盖已公开可下载的制度文件，培养方案、考试管理规定等未能采集（相关页面正文为空）。
